# Mars

**Decentralized real-world delivery data infrastructure for AI.**

Mars is not a normal delivery app. It is a Sui + Walrus + Seal data infrastructure prototype that turns real-world delivery activity into user-owned encrypted DataAssets, licenses access to buyers, aggregates licensed data in the buyer environment, and demonstrates AI utility through Demand Prediction and Dispatch Optimization.

## Core Idea

Traditional delivery platforms centralize the data generated by riders, merchants, and consumers. Mars separates ownership, access, and AI training:

- riders own mobility and route behavior;
- merchants own operational data such as prep times and category activity;
- consumers own demand signals such as order creation and value;
- AI buyers can license access without Mars becoming the owner of the raw plaintext dataset.

Mars coordinates ownership, licensing, payment, and access control. Aggregation happens only after licensed access.

## Two Data Layers

### Layer 1: Personal Data Layer

The simulator generates role-separated personal raw DataAssets:

| Data type | Owner | Example events |
| --- | --- | --- |
| `rider_mobility` | Rider | accepted, delivered, location, speed, idle time |
| `merchant_operations` | Merchant | order ready, prep time, merchant category |
| `consumer_demand` | Consumer | order created, order value, pickup/dropoff grids |

Each asset has one owner and can be encrypted for Walrus-style storage. Mars does not treat plaintext raw data as a centralized source of truth.

### Layer 2: Aggregated Training Dataset

The aggregator represents the buyer-side licensed data pipeline:

1. Load licensed DataAssets.
2. Decrypt them with mock MVP keys.
3. Merge rider, merchant, and consumer events by `order_id`.
4. Build grid-time demand prediction rows.
5. Build dispatch optimization states.
6. Export clean buyer datasets as JSON and CSV.

## Current Architecture

```text
simulator
  -> personal raw DataAssets
  -> mock encrypted Walrus blobs
  -> license manifest

aggregator
  -> fetch licensed assets
  -> mock decrypt
  -> merge events by order_id
  -> demand_prediction_dataset.json/csv
  -> dispatch_dataset.json

ai-agent
  -> demand_prediction model training/inference
  -> dispatch_optimization rule-based assignment
```

## Main Modules

- `simulator` — deterministic 7-day delivery activity simulator. Generates personal `rider_mobility`, `merchant_operations`, and `consumer_demand` DataAssets.
- `aggregator` — buyer-side licensed aggregation pipeline. Produces AI-ready demand and dispatch datasets.
- `ai-agent/demand_prediction` — trains a LightGBM model if available, otherwise sklearn GradientBoostingRegressor. If neither exists, training fails with an explicit dependency error.
- `ai-agent/dispatch_optimization` — configurable rule-based dispatch scoring and sample best-rider assignment.
- `scripts` — local orchestration scripts for the MVP AI pipeline.
- `contracts/mars` — Sui Move contracts for DataAssets, DataLicenses, escrow, settlement, and mock USDC.
- `walrus-uploader` — existing mock encrypted storage/DataAsset registration flow.
- `license-flow` — existing mock asset listing, purchase, license minting, and rewards flow.
- `seal-mock` — existing mock license verification and key release flow.
- `mars-app` — Expo/React Native ownership dashboard.

## Local AI Pipeline

Install simulator dependencies:

```bash
cd simulator
pnpm install
cd ..
```

Generate Sui testnet-compatible simulator wallets:

```bash
pnpm simulator:wallets
```

The simulator uses direct generated Ed25519 keypairs for testnet MVP users. zkLogin is production onboarding and is not integrated into the simulator.

Security warning: generated private keys are for testnet/hackathon demos only. Never use them for mainnet funds.

Install Python ML dependencies:

```bash
pip3 install -r aggregator/requirements.txt
pip3 install -r ai-agent/requirements.txt
```

Run the full local pipeline:

```bash
scripts/run_mars_ai_pipeline.sh
```

Equivalent manual steps:

```bash
pnpm simulator:wallets
pnpm simulator:generate
python3 aggregator/main.py
python3 ai-agent/demand_prediction/train_demand_model.py
python3 ai-agent/demand_prediction/predict_demand.py
python3 ai-agent/dispatch_optimization/assign_rider.py
```

Expected outputs:

- `simulator/output/raw_assets/`
- `simulator/output/orders.json`
- `simulator/output/mock_walrus/encrypted_assets/`
- `simulator/output/license_manifest.json`
- `aggregator/output/demand_prediction_dataset.csv`
- `aggregator/output/demand_prediction_dataset.json`
- `aggregator/output/dispatch_dataset.json`
- `ai-agent/demand_prediction/output/demand_model.pkl`
- `ai-agent/demand_prediction/output/demo_grid_predictions.json`
- `ai-agent/dispatch_optimization/output/sample_assignment.json`

The AI pipeline reads datasets directly from `aggregator/output/`. The `aggregator/output/buyer_dataset/` directory is an optional buyer delivery snapshot with copies of the final JSON and CSV files.

## AI Tasks

### Demand Prediction

Each row represents one grid and one 15-minute time window. The model predicts:

```text
future_30min_order_count
```

from supply/demand, merchant, rider, traffic, weather, and time features.

### Dispatch Optimization

Dispatch uses:

- incoming order state;
- candidate rider states;
- global demand state from the aggregated dataset.

In the MVP, candidate rider states are synthetic. A production dispatch engine would query live rider state from the platform.

The MVP uses rule-based scoring:

```text
dispatch_score =
w1 * distance_score
+ w2 * eta_score
+ w3 * rider_idle_score
+ w4 * fairness_score
+ w5 * demand_balance_score
```

Weights are configurable in `ai-agent/dispatch_optimization/dispatch_scoring.py`.

## Security Notes

- Personal raw data is role-owned by default.
- Aggregated training data is produced only after licensed access.
- The MVP simulator writes plaintext raw assets locally for inspection and mock encrypted envelopes for the local buyer pipeline.
- Mock encryption uses local development keys only.
- Production versions should use real client-side encryption, Walrus storage, Sui DataAsset registration, and Seal key release.
