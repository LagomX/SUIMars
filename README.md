# Mars

**Decentralized real-world delivery data infrastructure for AI.**

Mars is a Sui + Walrus + Seal protocol that turns real-world delivery activity into user-owned encrypted DataAssets, licenses access to AI buyers through on-chain DataLicenses, and demonstrates AI utility through demand prediction and dispatch optimization.

## Core Idea

Traditional delivery platforms centralize the data generated by riders, merchants, and consumers. Mars separates ownership, access, and AI training:

- **Riders** own mobility and route behavior data.
- **Merchants** own operational data such as prep times and category activity.
- **Consumers** own demand signals such as order creation and value.
- **AI buyers** can license access without Mars ever holding the raw plaintext dataset.

Data is encrypted before leaving the user's device. Decryption requires a valid on-chain `DataLicense`. The Seal key server enforces this condition cryptographically.

## Architecture

```
simulator/
  → 640 encrypted personal DataAssets (real Sui testnet wallets)
  → 16 043 simulated delivery orders

walrus-uploader/
  → AES-256-GCM encryption per DataAsset
  → Walrus testnet upload → blob_id
  → SealClient.encrypt(aesKey, { id: dataAssetObjectId }) → Seal key bundle
  → Sui register_data_asset(blob_id, contributors, data_type) → DataAsset object ID

contracts/
  → DataAsset registration script (register_data_assets.ts)
  → DataLicense purchase helper (prepare_data_license.ts)

seal-access/
  → Mock mode: DataLicense ownership check → return demo AES key → AES-GCM decrypt
  → Real mode (stub): Seal key server verifies seal_approve → releases AES key

aggregator/
  → Load licensed DataAssets
  → AES-GCM decrypt
  → Merge events by order_id
  → demand_prediction_dataset.csv / dispatch_dataset.json

ai-agent/
  → LightGBM / sklearn demand prediction
  → Rule-based dispatch optimization
```

## Modules

### `simulator/`
Deterministic 7-day delivery activity simulator. Generates real Sui Ed25519 testnet wallets (100 riders, 40 merchants, 500 consumers) and produces role-separated encrypted `PersonalDataAsset` objects with embedded Sui addresses.

| Data type | Owner |
|---|---|
| `rider_mobility` | Rider |
| `merchant_operations` | Merchant |
| `consumer_demand` | Consumer |

### `walrus-uploader/`
Encrypts each personal dataset with AES-256-GCM, uploads ciphertext to Walrus testnet (or mock), registers the AES key with Seal (`SealClient.encrypt`), and calls `register_data_asset` on Sui to anchor the blob on-chain. The raw AES key is never written to disk in real mode.

Outputs:
- `walrus-uploader/output/upload_manifest.json` — blob IDs + encryption metadata
- `contracts/output/data_asset_registry.json` — Sui DataAsset object IDs
- `seal-access/output/seal_key_registry.json` — Seal-encrypted key bundles

### `contracts/mars/`
Sui Move package with 5 modules:

| Module | Purpose |
|---|---|
| `data_asset.move` | Register encrypted Walrus blobs on-chain, track quality/price/reward pool |
| `data_license.move` | Mint DataLicense on purchase; `seal_approve` enforces Seal access policy |
| `escrow.move` | Delivery order lifecycle + USDC escrow |
| `settlement.move` | Split completed order escrow (85% merchant / 15% rider) |
| `usdc.move` | Mock TestUSDC coin for testnet |

TypeScript scripts in `contracts/`:
- `register_data_assets.ts` — calls `register_data_asset` on Sui for each upload manifest record
- `prepare_data_license.ts` — helper for purchasing DataLicense objects on testnet

### `seal-access/`
Seal access control and decrypt module. Supports two modes:

- **`MOCK_SEAL=true`** — Simulates DataLicense ownership check using demo AES keys. Decrypts locally. Useful for demos without a live Sui deployment.
- **`MOCK_SEAL=false`** — Real Seal mode: builds a PTB calling `data_license::seal_approve`, submits to Seal key servers, recovers AES key, decrypts Walrus blob locally. Requires deployed contracts and Seal-registered keys.

### `aggregator/`
Python buyer-side licensed data pipeline. Fetches licensed DataAssets, decrypts with mock MVP keys, merges rider + merchant + consumer events by `order_id`, and exports AI-ready datasets.

### `ai-agent/`
- **`demand_prediction/`** — LightGBM with Poisson objective (`objective="poisson"`) on 16-grid × 15-minute time series. Falls back to sklearn `HistGradientBoostingRegressor` if LightGBM is unavailable.
- **`dispatch_optimization/`** — Rule-based dispatch scoring: proximity (ETA), idle time, fairness, and per-grid demand balance.

### `mars-app/`
Expo/React Native ownership dashboard showing assets, licenses sold, USDC earned, and Seal access status per role.

## Developer Quick Start

### Prerequisites

```bash
# Node / pnpm
node >= 20
pnpm >= 9

# Python (for AI pipeline)
/usr/bin/python3   # macOS system Python 3.9 — has scikit-learn
# or
pip3 install -r aggregator/requirements.txt
pip3 install -r ai-agent/requirements.txt
```

---

### 1. Simulator — Generate real-world delivery event data

```bash
pnpm simulator:wallets    # create 100 riders, 40 merchants, 500 consumers (real Ed25519 keypairs)
pnpm simulator:generate   # produce 640 PersonalDataAssets + 16 043 delivery orders
```

Each `PersonalDataAsset` is role-separated (`rider_mobility`, `merchant_operations`, `consumer_demand`) and embeds the raw delivery events that belong to that wallet.
Private keys are written to `simulator/users/*.json` (gitignored — never use for mainnet).

---

### 2. Walrus — Encrypt and store datasets as decentralized blobs

```bash
# Mock mode — no Walrus CLI needed (uses local SHA-256 blob IDs)
MOCK_WALRUS=true pnpm walrus:upload

# Real Walrus testnet
pnpm walrus:upload
```

For each DataAsset this command:
- Encrypts the raw event JSON with **AES-256-GCM** (raw key never written to disk)
- Uploads the ciphertext blob to Walrus → receives a `blob_id`
- Wraps the AES key with **Seal** (`SealClient.encrypt`) → stores the encrypted key bundle

---

### 3. Sui — Register contributor-owned DataAssets and DataLicenses

```bash
# DataAssets are registered automatically by walrus:upload via register_data_asset PTB.
# On testnet, run the full on-chain flow:

cd contracts/mars && sui move test          # verify 21/21 tests pass
sui client publish --json > ../../publish-testnet.json

pnpm walrus:upload                          # registers DataAsset objects on-chain

pnpm --dir walrus-uploader chain:price-assets   # AI Agent: set_quality_and_price (AdminCap)
pnpm --dir walrus-uploader chain:list-assets    # Contributor: set_for_sale(true)

pnpm --dir walrus-uploader chain:mint-usdc      # mint TestUSDC for the buyer
pnpm --dir contracts prepare:data-license       # AI buyer: purchase_access → DataLicense minted

pnpm --dir walrus-uploader chain:distribute-rewards  # anyone: distribute_reward by weight_bps
```

See [`TESTNET.md`](./TESTNET.md) for the full deployment runbook.

---

### 4. Seal — Release AES keys only to licensed buyers

**Local demo — no Sui deployment needed:**

```bash
pnpm seal:decrypt:mock
```

Simulates the `DataLicense` ownership check using a local demo AES key.
To verify the access-denied path:

```bash
MOCK_BUYER_HAS_LICENSE=false pnpm seal:decrypt:mock
```

**Real Seal mode — after testnet deployment:**

```bash
MOCK_SEAL=false pnpm seal:decrypt
```

Builds a PTB calling `data_license::seal_approve` on Sui. Seal key servers dry-run the PTB — if the caller holds a valid `DataLicense`, the AES key is released and the Walrus blob is decrypted locally.

---

### 5. AI Training — Train ETA, demand, and dispatch models locally

```bash
scripts/run_mars_ai_pipeline.sh
```

Or step by step:

```bash
python3 aggregator/main.py                                   # merge licensed rider/merchant/consumer events
python3 ai-agent/demand_prediction/train_demand_model.py     # LightGBM demand model (Poisson objective)
python3 ai-agent/demand_prediction/predict_demand.py         # per-grid 30-min demand forecast
python3 ai-agent/dispatch_optimization/assign_rider.py       # best-rider dispatch scoring
```

## Contracts

```bash
cd contracts/mars
sui move build
sui move test   # 21/21 tests pass
```

The `seal_approve` entry point in `data_license.move` is the on-chain gate Seal key servers call before releasing the AES decryption key. It verifies:
1. The Seal IBE identity matches this specific DataAsset (`bcs::to_bytes(object::id(asset)) == id`).
2. The caller holds a valid `DataLicense` for this asset (`license.data_asset_id` match + `license.buyer == ctx.sender()` + perpetual type).

Test coverage includes `seal_approve` happy path, wrong-asset-id abort, and non-buyer-caller abort (21 tests total across `data_asset`, `data_license`, `escrow`, and `settlement`).

## Security Notes

- Personal raw data is role-owned; aggregation happens only after licensed access.
- Ciphertext only is uploaded to Walrus; the raw AES key never leaves the user's environment in production.
- In real Seal mode, the AES key is recovered via Seal's threshold key servers — not from any local file.
- `register_data_asset` rejects empty `blob_id` or `data_type` — no DataAsset can be created without a valid Walrus blob reference.
- `raise_dispute` uses a strict `<` boundary against `delivered_at + 24h`, so the dispute window and the 24-hour auto-complete window can never fire in the same block.
- `seal-access/input/encryption_key.demo.json` is a **demo-only** artifact clearly marked unsafe.
- The `simulator/users/` directory (containing private keys) is gitignored.
