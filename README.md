# Mars

## What Is This Project

Mars is a data ownership protocol for the gig economy. It lets delivery riders, merchants, and consumers own the data they generate — and earn revenue when AI companies license that data.

Built on Sui + Walrus + Seal, Mars treats personal activity data as a financial asset. Every delivery trip, every order accepted, every purchase made becomes a contributor-owned `DataAsset` on-chain. AI companies buy access through `DataLicense` NFTs. Contributors earn USDC every time their data is used.

The current implementation runs end-to-end on Sui testnet with 640 simulated contributors (100 riders, 40 merchants, 500 consumers) generating real on-chain objects, real Walrus blobs, and real Seal-gated decryption.

---

## What Problem It Solves

Today, gig platforms capture and monetize all behavioral data generated by their workers and users. Riders don't own their route history. Merchants don't own their demand patterns. Consumers don't own their purchasing behavior. The data is worth billions to AI companies building logistics, demand prediction, and dispatch models — but none of that value reaches the people who created it.

There is also no way for an AI buyer to verify: who contributed the data, whether they consented, whether the data was tampered with, or whether they actually paid the right people.

Mars solves both sides of this:

- **Contributors** get cryptographic ownership of their data, granular consent controls, and automatic revenue share.
- **AI buyers** get verifiable provenance, tamper-evident commitment roots on-chain, and Seal-enforced access control that can't be bypassed even if the platform is compromised.

## How It Works

**1. Contributors opt in and data is aggregated into shards**

Each contributor's personal data (rides, orders, purchases) is validated and collected with a scoped listing authorization — a signed consent record specifying what can be listed, where, and until when. Authorized assets are then aggregated into `DatasetShards` grouped by role and time epoch.

**2. Shards are encrypted and anchored on-chain**

Each shard is gzip-compressed, then AES-256-GCM encrypted with a fresh random key. The ciphertext is uploaded to Walrus (decentralized storage) and a Walrus blob ID is returned. Simultaneously, SHA-256 commitment roots over the contributor manifests, listing authorizations, and accounting records are computed and submitted on-chain via a Sui `register_data_shard` transaction — creating a shared `DataAsset` object. The AES key is immediately handed to Seal (threshold IBE) and discarded — it never touches disk.

**3. AI agent scores and prices the data**

A protocol-side AI agent analyzes the on-chain shard metadata and produces quality scores (0–100) and USDC prices. These are written to each `DataAsset` via `set_quality_and_price` (requires `AdminCap`).

**4. AI buyers purchase DataLicenses**

A buyer calls `purchase_access` with exact USDC payment. This mints a `DataLicense` NFT to the buyer's wallet and routes the payment into the `DataAsset` reward pool for contributors to claim. One PTB can batch-purchase licenses for an entire dataset in a single transaction.

**5. Seal releases the decryption key — and only to license holders**

When the buyer wants to decrypt, they build a PTB calling `seal_approve(id, license, asset)`. Seal key servers execute this as a dry-run — if the buyer actually holds a valid `DataLicense` for that exact `DataAsset`, the threshold IBE key is released and the AES key is reconstructed client-side. The buyer then fetches the Walrus blob and decrypts locally. If the buyer has no license, `seal_approve` aborts and the key is never released.

**6. Decrypted data feeds AI models**

Licensed shard data is aggregated into demand prediction datasets (grid × time window) and dispatch optimization candidate states. A LightGBM model is trained on the demand data; a rule-based scoring function handles dispatch assignment.

## Results

Running `pnpm mars:e2e:testnet` against Sui testnet produces:

| What | Where |
|---|---|
| 640 real Sui Ed25519 wallets | `simulator/users/all_users.json` |
| 640 PersonalDataAsset JSON files | `simulator/output/raw_assets/` |
| 16 043 synthetic delivery orders | `simulator/output/orders.json` |
| DatasetShards (one per data_type × region × epoch) | `walrus-uploader/output/shards/` |
| Real Walrus blob IDs (testnet) | `walrus-uploader/output/upload_manifest.json` |
| Sui DataAsset objects with commitment roots | `contracts/output/data_asset_registry.json` |
| Seal-encrypted AES key bundles | `seal-access/output/seal_key_registry.json` |
| On-chain quality scores and USDC prices | `ai-pricing/output/pricing_apply_receipt.json` |
| Sui DataLicense NFTs (testnet) | `contracts/output/data_license_registry.json` |
| AI-ready demand prediction dataset | `aggregator/output/demand_prediction_dataset.csv` |
| Trained LightGBM demand model | `ai-agent/demand_prediction/output/demand_model.pkl` |
| Dispatch assignment output | `ai-agent/dispatch_optimization/output/sample_assignment.json` |

Every step is verifiable on-chain: the `DataAsset` commitment roots allow a buyer to confirm that the shard content, contributor list, and authorization records match exactly what was registered. The Seal access gate means data can only be decrypted after a real on-chain `DataLicense` purchase — not by the platform, not by the uploader, and not by anyone else.

## Run It

```bash
# Prerequisites: node >= 20, pnpm >= 9, python3, sui CLI
pnpm install && pnpm --dir simulator install && pnpm --dir walrus-uploader install
pnpm --dir seal-access install && pnpm --dir contracts install
python3 -m pip install -r aggregator/requirements.txt ai-agent/requirements.txt

cp walrus-uploader/.env.example walrus-uploader/.env   # fill SUI_PRIVATE_KEY, ADMIN_CAP_ID
cp seal-access/.env.example seal-access/.env
cp contracts/.env.example contracts/.env               # fill USDC_TREASURY_CAP_ID

pnpm mars:e2e:testnet
```

See [TESTNET.md](TESTNET.md) for step-by-step instructions and [ARCHITECTURE.md](ARCHITECTURE.md) for a full module reference.
